# builder — агент для больших HTML+JS приложений на локальной модели

Решает главную проблему Zed + Gemma-E2B: Zed отправляет ~10 тыс. токенов системного
промпта, требует переписывать файл целиком и тянет за собой всю историю диалога —
к третьей правке контекст переполняется, и модель «ломается».

## Принцип

| Проблема в Zed | Как решено здесь |
|---|---|
| Системный промпт ~10 000 токенов | Свой промпт ~200 токенов |
| Файл 500+ строк = ответ 6000+ токенов | Части по 30–120 строк, приложение 500 строк = 5–9 маленьких ответов |
| История диалога растёт, к 3-й правке модель деградирует | Состояние на диске (`project.json`, `parts/`), каждый запрос — свежий контекст одинакового размера |
| Правка = генерация всего файла заново | Правится только одна часть, остальное не трогается |
| Ошибки замечает пользователь | `node --check` + проверка id + дубликаты имён после каждой записи, ошибка сразу возвращается модели |
| JSON-инструменты иногда ломаются | грамматика llama-server страхует; фолбэк — парсинг кода из ```блока```, имена частей нормализуются автоматически |

Сборка: `parts/NN-имя.ext` → `dist/index.html` (`.html` → body, `.head.html` → head,
`.css` → `<style>`, `.js` → `<script>`).

## Быстрый старт

```bat
1) builder\START_server.bat        сервер уже работает? — просто пропустите
2) python builder\agent.py new "игра змейка: счёт, пауза, рекорд в localStorage" --name snake
3) builder\BUILD_OPEN.bat          пересобрать и открыть в браузере
```

Дальше — сколько угодно правок, промпт не растёт:

```bat
python builder\agent.py step "добавь ускорение каждые 5 яблок"
python builder\agent.py fix                     автопроверка + исправление
python builder\agent.py part 40-logic.js        переписать одну часть
python builder\agent.py status                  состояние и проверки
python builder\check.py                         только проверки (без модели)
```

Опции агента: `--cooldown 4` (пауза после каждого запроса, с), `--max-tokens 3072`,
`--port 8080`, `--project <путь>` (по умолчанию последний проект).

## Безопасный, но быстрый режим GPU

Отключения ноутбука происходили на резких и длинных пиках нагрузки. Профиль
`START_server.bat` повторяет единственную конфигурацию без единого отключения
(Gemma-E2B + RX 6800M + паузы): короткие промпты (2–5 тыс. токенов), короткие
ответы (≤ 3072 токенов), обязательная пауза 4 с после каждого запроса (см.
`llm.py: cooldown`), размышления только на этапе планирования (бюджет 512),
контекст 32768 — больше не нужно, потому что промпты не растут. Защита самого
сервера (одна видеокарта, порции по 128 токенов, без прогрева) — в `start.ps1`.

Работайте от сетевого адаптера. Если отключения всё же появятся — `--cooldown 8`
или профиль `gpueco`/`cpu` (агенту всё равно, скорость ниже).

## Что проверяется автоматически (check.py, без GPU)

- синтаксис каждой JS-части через `node --check`;
- `getElementById/querySelector('#...')` ссылается на существующий в HTML `id`;
- дубликаты глобальных имён между частями (конфликты склейки);
- непарные `<div>/<canvas>/<script>...`;
- слишком длинные части (> 220 строк — предупреждение).

## Структура проекта-приложения

```
workspace/<имя>/
  project.json     задача, план, статус (машиночитаемо)
  PROJECT.md       то же человеком + заметки
  parts/           NN-имя.ext — части по 30–120 строк
  dist/index.html  результат сборки (открывать в браузере)
```

Проекты обычные папки: части можно править руками, а `agent.py step` продолжит с места,
где остановились — контекст диалога для этого не нужен.

## Что проверить, если что-то не так

- Сервер: `curl http://127.0.0.1:8080/health` → `{"status":"ok"}`; иначе `START_server.bat`.
- Логи скорости: агент печатает промпт/ответ токенов и ток/с после каждого запроса.
- `python builder/check.py --selftest` — проверка самого чекера (без модели).
- Если модель зациклилась на части — `agent.py part <имя>` перепишет её со свежим контекстом.
